New bottleneck — human understanding

Human understanding — attention span.

Lose control. Low confidence releasing code to production. Shifting-right a heavy QA process.

We need to better use our attention to maxium the outcome!

Failure modes

Attention is NOT well spent when:

  • Oversized unit of work
  • Handoffs
  • Context switching
  • Waiting for others
  • Early optimization / over implementation

Promote

  • Small vertical slice as the unit of the work — what we can understand and kick off within 5 mins
    • Not tickets as coordination between roles
    • The slice is part of the work, not a board people visit between meetings
  • Shared working space — everything lives in the codebase; push everyone there
  • Pairing / mobbing across roles, fewer handoffs
    • Everyone becomes a builder; roles blur
    • Work is not linear — specialty still matters; the process does not
  • Good engineering practice matters more

Closing

We manage attention, so that we can manage our understanding. Only understanding can give us the confidence needed for production. Without confidence, we might build a bunch, still not able to ship.

Do not optimize for agent emit — optimize for human understanding. Take the step to ease human understanding, not for how big the agent can accept.

Invest in building the system and tooling. So we can go faster with confidence.

New ways of working — across-role pairing, non-linear process.
